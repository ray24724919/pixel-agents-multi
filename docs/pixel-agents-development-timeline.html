2026-05-27 至 2026-05-29
W2 Agent lifecycle

Agent 採用、狀態與安全操作基礎

這一波讓 Codex / Claude agents 更可靠地顯示，並建立 Hide、Archive、Kill 的語意。

  • Codex external sync，支援同 cwd 多 thread 與外部 thread 採用。
  • Claude chat-mode filter，避免非工作型聊天污染 agent 列表。
  • Pause / Resume、Hide / Archive / Kill action model。
  • No-workspace fallback，支援不開資料夾時當跨專案狀態板使用。
  • Provider discovery 與 Codex no-workspace fallback review 後修正。
  • 開始把 executor 報告固定寫入 docs/roadmap/supervision/reports/。

先處理 PATH、Node、VS Code extension host、工作樹乾淨度與 executor 派工方式，讓專案能在新機器上正常 build、test、package、install。

  • 開始使用獨立 worktree 讓 executor 平行工作，避免髒工作樹互相污染。
2026-06-02
W4 Private release

私有 extension identity 與產品規格化

這一波把 fork 從 public Pixel Agents 分開，並把 Agent Center、Usage Intelligence、Team/Lab Mode 寫成產品規格。

  • 新增 release verification scripts：identity、VSIX contents、installed extension。
  • 私有 extension id 固定為 raychen.pixel-agents-multi。
  • VSIX 名稱固定為 pixel-agents-multi-<version>.vsix。
  • 資料目錄切到 ~/.pixel-agents-multi，避免和 public extension 混用。
  • 建立 Agent Center 2.0、Usage Intelligence、Team/Lab Mode 長期設計文件。
  • 加入 Codex thread title sync，CLI 改名後 webview 也能同步更新。
2026-06-02
W5 Agent Center

Agent Center 從面板變成控制台

Office 不再是唯一入口，Agent Center 開始承擔管理、使用量和 timeline 的頁面級導航。

  • 新增 Agent Center navigation shell，Office、Agents、Usage、Timeline 成為頁面級 destinations。
  • Agents page 支援 provider、status、project、team、search、sort。
  • Usage Intelligence live page 顯示 provider、project、ledger、token mix、quota signals。
  • Timeline page 管理事件歷史、搜尋、篩選、retained action history。
  • 移除重複 Agents toolbar button，讓 UI 上下入口不重複。
2026-06-02 至 2026-06-03
W6 Usage History

Usage 從即時摘要走向本地歷史

使用量不再只存在當下畫面，開始有 append-only local store、ingestion、 read model、webview bridge 與 History UI。

  • 建立 ~/.pixel-agents-multi/usage/usage-v1.jsonl。
  • 支援 usage delta、artifact estimate、rate-limit snapshot。
  • 加入 durable dedupe，避免 cumulative provider snapshots 重複計算。
  • Usage History page 支援 Live / History segmented view。
  • CSV copy 預設 redacted paths，不輸出 raw transcript path。
2026-06-03
W7 Delegation

Supervisor / child-agent 可視化

這一波解決「主 supervisor 派 subagents 後，畫面卻像 idle」的產品問題。

  • 新增 delegation visibility foundation，辨識 supervisor 正在帶 team 工作。
  • Delegation timeline events：started、progress、completed、failed、cancelled。
  • Office delegation visuals，讓 supervisor 和子代理的工作關係在畫面上可見。
  • Codex spawn delegation visuals live QA，修正 current Codex spawn_agent 顯示。
  • Delegation regression hardening，避免 unrelated agent_id tool output 被誤判。
2026-06-03
W8 Timeline Replay

Timeline 持久化與 Session Replay MVP

Timeline 從 in-memory UI 變成可持久化、可回放的 normalized event stream。

  • 建立 ~/.pixel-agents-multi/timeline/timeline-v1.jsonl。
  • Timeline page 讀取 persisted history，保留 removed/hidden/killed agents 的 action history。
  • Session Replay MVP：用 normalized timeline events 重建狀態與事件游標。
  • Event row 可直接 cue replay session/frame，current frame 會在 event list 標記。
  • Overlay label 改成 project、agent name、status 三行，狀態點移到第三行。
  • 最新微調：第一行改為 project (provider)，前兩行使用藍色字。
2026-06-04
W9 Handoff foundation

Replay 打磨與 Handoff 模型

這一波開始把「看得到歷史」推向「能產出可交接成果」。

  • Replay navigation polish：First、Last、ArrowLeft、ArrowRight、Home、End、Space。
  • Replay controls 對 empty / single-frame sessions 會正確 disabled。
  • Handoff draft model：從 normalized Timeline + Usage 產生安全 Markdown draft。
  • Handoff redaction：遮蔽 absolute local paths、raw prompt、raw tool output、credentials。
  • Handoff UI：Timeline / Session Replay 內新增 Create Handoff、Markdown preview、Copy Markdown。
  • Handoff UI 維持 local-only，不寫檔、不做 git operation、不分享 raw transcript。
2026-06-04
W10 Repo artifacts

Handoff 從草稿變成 repo-centered artifact

W10 把 W9 的 local preview 推進成可追溯、可 review 的本機 artifact， 但仍維持不自動 stage、commit、push 或分享 raw transcript。

  • W10-A：Write to Repo 寫入 docs/agent-handoffs/，由 extension host 決定安全 repo path。
  • W10-B：新增 Recent Handoffs artifact library，支援 refresh、open、safe metadata 與 handoff timeline events。
  • W10-C：每份 Markdown handoff 搭配 .handoff.json sidecar，保存 artifact id、status、updatedAt 等結構化 metadata。
  • W10-D：新增 local status actions：Mark reviewed、Mark stale、Reset draft，僅更新 sidecar，不改 Markdown body。
  • 安全邊界：webview 不送任意 filesystem path，不輸出 raw prompt/tool output，不做 cloud sync 或 git mutation。
2026-06-04 至 2026-06-05
W11 Dispatch queue

Artifact 走向 executor-ready work package 與 queue

W11 建立 supervisor 派工的中段：從 reviewed handoff 產生 executor package， 追蹤 dispatch / execution 狀態，並把 completion 檢查保持為 read-only。

  • W11-A：Recent Handoffs 可產生 copy-only dispatch prompt，引用 handoff path 而不嵌入 Markdown body。
  • W11-B：建立 docs/roadmap/supervision/work-packages/handoffs/ work-package queue 與 package prompt。
  • W11-C：sidecar 增加 optional execution record，可 link visible agent 並更新 execution status。
  • W11 remaining：Handoff Queue 顯示 needs dispatch、active/waiting、blocked、report ready、done 等 grouping。
  • 新增 executor launch、completion refresh、report open timeline events；report/branch scan 只讀，不 checkout、不 merge。
2026-06-05 至 2026-06-06
W12 Executor launch QA

Codex / Claude executor launch 與 live validation

W12 把 package-backed handoff 從 copy prompt 推進到可直接 launch executor， 並用 installed VSIX 與 user-assisted QA 找出真實 Windows / VS Code 問題。

  • W12-A：Recent Handoffs 與 Handoff Queue 分別提供 Launch Codex / Launch Claude。
  • Claude handoff prompt 以 argv 傳入 terminal，不用 shell command string 拼接，Codex path 維持 provider-specific 行為。
  • W12-B/W12-C：build、test、package、install、identity checks 通過；Computer Use live click QA 被 Windows automation 權限擋下，未誤標為完成。
  • W12-D：user-assisted QA 驗證 Codex 與 Claude launch 都能寫入 sidecar execution metadata 並顯示 active。
  • 修正 Codex CLI discovery、handoff row pathological wrapping、Claude terminal title prefix。
2026-06-06
W13 Completion review

Handoff supervisor review workflow 收尾

W13 補上 executor 回報後 supervisor 判讀的最後一段，將 report cues、 branch facts、merge readiness 與 status controls 做成 read-only / manual-first 的決策面。

  • W13-A：completion review model 解析 bounded executor report cues、validation lines、changed files 與 risk/follow-up。
  • W13-B：Recent Handoffs 與 Handoff Queue 顯示 review status badges、checklist cues 與 recommended next action。
  • W13-C：merge readiness panel 顯示 branch/report/validation/warning cues，Copy merge checklist 只複製安全文字。
  • W13-D：把 primary、reference、local maintenance/status actions 分組，Recent Handoffs 與 Queue 共用 action renderer。
  • W13-E/W13-F：dispatch / execution status 改成 compact select controls，並把 select option model 抽出成可測 helper。
  • 安全邊界保持不變：沒有 merge button，沒有 git mutation，沒有 raw report body、transcript 或 absolute path 外洩。

常用 release 指令

目前推薦用 repo 腳本，不手動敲散落的 build/package/install 指令。

  • npm run build：type-check、lint、extension build、webview build。
  • npm run release:local：build、identity verify、VSIX verify、package、install、installed verify。
  • npm run verify:installed：確認 VS Code 裝的是私有版，不是 public Pixel Agents。

下一步

建議下一包：W14 Release QA / Handoff Workflow Polish

W10-W13 已把 handoff 從 draft 推到 repo artifact、artifact library、work package queue、 executor launch、completion review、merge readiness 與 compact status controls。 下一步建議進入 W14：針對 installed VSIX 做 release QA、真實 handoff workflow live validation、 dense queue 視覺 polish，以及 launch / completion / review 流程的使用者操作細節整理。

Product rule: 後續若擴充 Handoff，仍應維持 local-only、user-reviewed、 redacted by default。不要把 raw transcript export 或自動 git operation 放進預設路徑。Team/Lab Mode、cloud sync 或跨人共享應等本機 supervisor workflow 經過更完整 live validation 後再評估。
